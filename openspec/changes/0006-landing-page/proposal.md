# 0006 — Landing page

## Outcome

A dark, animated single page at `https://espin086.github.io/Stocks/` that explains
what quantfolio is in the time someone gives a link before closing the tab, and
sends them to one of two commands:

```bash
pip install quantfolio-cli
docker run -p 8787:8787 -v quantfolio:/data espin086/quantfolio serve --host 0.0.0.0
```

Published automatically from `main` by GitHub Actions.

## Why

A README explains a tool to someone already reading the repository. The people
worth reaching — someone who saw a link, a hiring manager, a person who wants to
optimize a portfolio and does not yet know this exists — decide in about eight
seconds, and they decide on something moving.

This tool's output is unusually well suited to that. An efficient frontier drawing
itself along its curve *is* the explanation of what mean-variance optimization
does. A terminal typing `qf optimize markowitz` and returning a weights table shows
the product working, in the product's own voice.

It comes after 0005 because a landing page for something nobody can install yet is
a liability, not an asset.

## What changes

- **New capability `landing-page`.**
- `site/` — a Vite + TypeScript project, separate from `frontend/` (0004). They
  share design tokens but not a build: the app is behind a token and optimizes for
  interaction, the page is public and optimizes for first paint.
- A GitHub Actions workflow building `site/` and deploying to GitHub Pages on push
  to `main`, using the official Pages deployment action with `pages: write` scoped
  to that job alone.
- Design tokens extracted so the page and the app look like one product.

## Design direction

Dark-first, not dark-mode-toggled. The subject is a terminal and a chart, both of
which live natively on a dark ground; a light variant would be a worse version of
the same page. Type-led, high contrast, one accent colour used sparingly on the
curve and the call to action.

Animation is scroll-driven and diegetic — it animates the *product's actual
output*, not decoration around it:

1. **Hero** — an efficient frontier draws along its path; the max-Sharpe point
   lands last and labels itself.
2. **Terminal** — a real `qf` command types itself and returns real output. The
   text is the actual recorded output of that command, not invented.
3. **Capabilities** — scroll-pinned sections, one per milestone, each with the
   command and the chart it produces.
4. **Honesty section** — the in-sample vs. walk-forward Sharpe gap, animated as
   one number falling to the other. This is the tool's actual thesis and the most
   interesting thing on the page.
5. **Install** — two commands, copy buttons, nothing else.

## Non-goals

- **No claims about unshipped features.** The page describes what the released
  version does. A capability still in `openspec/changes/` may appear only under an
  explicit roadmap heading.
- No analytics, tracking, cookies, or third-party scripts. There is nothing to
  measure that is worth a consent banner.
- No blog, docs site, or changelog rendering. The page links to the repository.
- No newsletter capture, no contact form, no backend of any kind.
- No 3D or WebGL. It would cost more bundle than the idea is worth here.
- Not a replacement for the README, which stays the reference.

## Risks

| Risk | Mitigation |
|---|---|
| Animation makes the page slow or unusable on a mid-range phone | Hard Lighthouse and bundle budgets as CI gates; animation libraries code-split; the page is readable before any of them load |
| Motion causes discomfort, or the page is unusable to someone who needs reduced motion | `prefers-reduced-motion` renders every animated element in its final state; no information is conveyed only by motion |
| The page overstates the tool | Every claim maps to a shipped, specified capability; the not-investment-advice disclaimer is on the page, not just in the repo |
| Marketing copy and reality drift apart as the tool changes | The install commands and the version shown are generated at build time from the repository, so a stale page fails the build rather than lying |
| A fabricated "example output" screenshot | Terminal content is a recorded transcript of a real run, checked into `site/`, regenerated by a script |
