# storage — spec delta (0001)

The database is reachable only through a port. SQLite is the first adapter behind
it, not the interface itself.

## ADDED Requirements

### Requirement: Storage port

All persistence SHALL go through protocols in `sobres.data.storage.base`.
No module outside `sobres.data.storage.adapters` SHALL import a database
driver.

#### Scenario: Drivers are confined to adapters
- **WHEN** the codebase is inspected
- **THEN** `sqlite3`, `sqlalchemy`, and any other database driver SHALL be
  imported only under `data/storage/adapters/`
- **AND** a test SHALL assert this by scanning imports, so the boundary is
  enforced rather than remembered

#### Scenario: Call sites depend on the port
- **WHEN** any code needs to read or write persisted data
- **THEN** it SHALL accept a repository protocol
- **AND** SHALL NOT construct a connection, build SQL, or name a backend

#### Scenario: Backend selection is configuration
- **WHEN** the storage backend is chosen
- **THEN** it SHALL come from a URL in configuration (`SOBRES_DB_URL`),
  defaulting to `sqlite:///<user-data-dir>/sobres.db`
- **AND** switching backends SHALL require no change to any call site

#### Scenario: Unknown backend
- **WHEN** the configured URL names a backend with no registered adapter
- **THEN** the system SHALL exit 3 naming the URL scheme and listing the
  backends this build supports

### Requirement: Backend conformance suite

A backend is supported when it passes one shared test suite, not when someone
believes it works.

#### Scenario: One suite, every adapter
- **WHEN** a storage adapter is registered
- **THEN** the shared conformance suite SHALL run against it
- **AND** adding a backend SHALL require adding it to a fixture list and nothing
  else in the suite

#### Scenario: The suite defines the contract
- **WHEN** the conformance suite runs
- **THEN** it SHALL cover round-tripping every persisted type, upsert semantics,
  transaction rollback, concurrent readers during a write, migration from every
  prior schema version, and the exact exceptions raised on conflict and on
  constraint violation

#### Scenario: Behavior is identical across backends
- **WHEN** the same sequence of operations runs against two adapters
- **THEN** the observable results SHALL be identical
- **AND** where a backend cannot match, the adapter SHALL compensate rather than
  let the difference reach a call site

### Requirement: Portable data model

The schema SHALL stay within the capability intersection of SQLite, PostgreSQL,
and DuckDB — the named candidate backends.

#### Scenario: Portable types only
- **WHEN** a column is defined
- **THEN** its type SHALL be one of the portable set: integer, real, text,
  boolean, UTC timestamp, or JSON-encoded text
- **AND** backend-specific types SHALL NOT appear in the shared schema

#### Scenario: Timestamps are unambiguous
- **WHEN** a timestamp is stored
- **THEN** it SHALL be stored as UTC and read back as a timezone-aware UTC value
- **AND** SHALL NOT rely on any backend's local-time handling, which differs
  between all three candidates

#### Scenario: Decimal-free monetary handling
- **WHEN** a monetary or return value is stored
- **THEN** it SHALL be a float, matching what `core/` computes on
- **AND** formatting SHALL happen at the edge, per 0001's rendering rules

#### Scenario: No backend-specific SQL in shared code
- **WHEN** a query is expressed
- **THEN** it SHALL be built through the shared expression layer
- **AND** any statement that cannot be expressed portably SHALL live behind a
  named method on the adapter, with every adapter implementing it

#### Scenario: Identifier generation is not delegated
- **WHEN** a row needs an identifier
- **THEN** it SHALL be generated by the application
- **AND** SHALL NOT depend on a backend's autoincrement or sequence semantics

### Requirement: Migrations are backend-neutral

#### Scenario: One migration set
- **WHEN** a migration is written
- **THEN** it SHALL apply to every supported backend without branching on the
  backend, or SHALL be rejected in review

#### Scenario: Applied through the port
- **WHEN** migrations run
- **THEN** they SHALL be driven by the adapter, so a backend with different DDL
  transaction semantics is handled in one place

### Requirement: Transactions and failure semantics

#### Scenario: Unit of work
- **WHEN** a repository operation spans more than one statement
- **THEN** it SHALL run in one transaction, committing or rolling back as a unit

#### Scenario: Errors are translated
- **WHEN** a backend raises a driver-specific exception
- **THEN** the adapter SHALL translate it into sobres's own error taxonomy
- **AND** no driver exception SHALL escape `data/storage/adapters/`

#### Scenario: Contention
- **WHEN** two writers contend
- **THEN** the adapter SHALL retry with backoff up to a bounded limit, and raise
  a translated error after that, rather than surface a locked-database message

### Requirement: SQLite as the default adapter

#### Scenario: Default backend
- **WHEN** no `SOBRES_DB_URL` is configured
- **THEN** SQLite SHALL be used, requiring no server and no additional install

#### Scenario: SQLite-specific tuning stays in its adapter
- **WHEN** WAL mode, busy timeout, and foreign-key pragmas are applied
- **THEN** they SHALL be set by the SQLite adapter alone
- **AND** SHALL NOT appear in shared code, where another backend would ignore them

#### Scenario: The single-file property is preserved as the default, not the contract
- **WHEN** SQLite is in use
- **THEN** one file SHALL hold the entire local state, as 0005 relies on for its
  volume mount
- **AND** documentation SHALL present this as a property of the default backend
  rather than of the system

### Requirement: Provider protocols are the same pattern

#### Scenario: Consistency with the data providers
- **WHEN** any external dependency that might later be swapped is introduced —
  a market-data vendor, a storage backend, a solver
- **THEN** it SHALL sit behind a `Protocol` in this codebase's own namespace,
  with a conformance suite where more than one implementation is plausible
- **AND** its library types SHALL NOT appear in signatures outside its adapter
